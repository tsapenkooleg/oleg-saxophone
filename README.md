# Олег Цапенко — персональный сайт саксофониста

React 19 · TypeScript · Vite · GSAP / ScrollTrigger. Статический лендинг без сервера, регистрации и автоматического воспроизведения музыки.

## Локальный запуск

```powershell
npm install
npm run dev
```

Открыть **http://localhost:5180**. Отдельный порт выбран, чтобы не конфликтовать с соседними проектами.

```powershell
npm run typecheck
npm run build
npm run preview
```

Production-просмотр: **http://localhost:5181**. На хостинг загружается содержимое `dist/`. Проект рассчитан на размещение в корне домена.

## Основные файлы

- `src/App.tsx` — все секции и анимации.
- `src/components/VideoSection.tsx` — видео, кнопка Play, штатное управление и сообщение об ошибке.
- `src/components/PhotoDialog.tsx` — модальный фотопросмотр, Escape, удержание и возврат фокуса.
- `src/components/ArtistImage.tsx` — responsive WebP, размеры и безопасное состояние при ошибке изображения.
- `src/config.ts` — единое место для контактов и медиа.
- `src/styles.css`, `src/fonts.css` — оформление, адаптивность, локальные шрифты, reduced motion.
- `index.html`, `public/robots.txt`, `public/favicon.svg` — SEO и метаданные.
- `docs/screenshots/` — desktop 1440×900 и mobile 390×844.
- `docs/qa/` — отчёт проверок и Lighthouse.

## Публикация на Cloudflare Workers

Сайт опубликован как **Cloudflare Worker со статическими ассетами**: **https://oleg-saxophone.tsapenkooleg89.workers.dev**. HTTPS включён, проект работает на бесплатном тарифе.

Настройки Git-интеграции в Dashboard:

- репозиторий — `tsapenkooleg/oleg-saxophone`;
- production branch — `github-publication`;
- build command — `npm run build`;
- deploy command — `npx wrangler deploy`;
- root directory — `/`.

Каждый push в `github-publication` запускает сборку и публикует новую версию. Конфигурация Worker находится в `wrangler.jsonc`, точка входа — `worker/index.js`.

### Range для видео

Workers static assets отдают файлы целиком и не поддерживают HTTP Range; из-за этого Safari может не воспроизводить видео. Проверка на живом Worker показала, что Range-запрос к URL существующего ассета edge обрабатывает напрямую, даже при `run_worker_first`. Поэтому видео отдаётся по отдельному нестатическому пути `/stream/sax_1.mp4` — для таких путей Worker вызывается всегда. Сам файл лежит в `dist/media/sax_1.mp4` и читается через `env.ASSETS`.

Обработчик:

- без заголовка `Range` отдаёт видео с `Accept-Ranges: bytes`;
- на корректный диапазон отвечает `206 Partial Content` с `Content-Range` и точным фрагментом;
- на полный диапазон `bytes=0-` стримит файл без буферизации;
- на некорректный диапазон отвечает `416 Range Not Satisfiable`;
- на методы кроме `GET`/`HEAD` отвечает `405`.

Остальные ассеты, включая исходный `/media/sax_1.mp4`, обслуживаются напрямую, без вызова Worker.

В `npm run dev` и `npm run preview` Worker не запускается, поэтому Vite перенаправляет `/stream/sax_1.mp4` на `/media/sax_1.mp4` (302). Локально видео воспроизводится с обычной поддержкой Range статического сервера Vite. Ссылка в сообщении об ошибке плеера ведёт на прямой файл `/media/sax_1.mp4`.

```powershell
npm run build
node --test worker/range.test.mjs
npx --yes wrangler@latest deploy --dry-run
npx --yes wrangler@latest dev --port 5190
```

Локальная проверка production-сборки без Worker: `npm run preview` → **http://localhost:5181**. Проверка Worker: `http://127.0.0.1:5190`.

Ограничения бесплатного тарифа Workers: 100 000 запросов в сутки, не более 25 МиБ на файл статики. Видео занимает 19,3 МБ и проходит с запасом.
